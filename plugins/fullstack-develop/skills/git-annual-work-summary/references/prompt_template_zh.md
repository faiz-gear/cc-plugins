### 非常重要的分析原则

1) **以工程语义为主**：基于 Conventional Commits 的类型、scope、breaking change、关键关键词，推断意图与价值；不要停留在数量统计。
2) **以“工作主题”组织**：把零散提交聚合成若干高层主题（按系统能力、交付闭环、质量稳定性、效率自动化等）。
3) **核心项目加权**：`{{CORE_PROJECTS}}` 必须各自作为独立主题，篇幅明显高于其他项目；写出“问题→方案→落地→效果”的闭环。
4) **克制推断**：允许合理工程推断（效率提升、稳定性提升的原因），避免无事实支撑的夸大或虚构量化收益。
5) **第一人称、可述职**：不出现“从 commit 可以看出你…”，统一用“我…”，风格专业克制，可被管理者引用。
